| TLS 1.0のサポート終了 | 更新日：2019年1月10日（PT） | 2019年2月11日（PT）に、Adobe Analytics レポートはTLS （Transport Layer Security） 1.0暗号化をサポートしなくなります。 この変更は、最高のセキュリティ基準を維持し、顧客データの安全性を促進するための継続的な取り組みの一部です。 2019年2月11日以降にAdobe Analytics レポートに接続できない場合は、ブラウザーを[最新バージョン &#x200B;](https://experienceleague.adobe.com/docs/analytics/admin/sys-reqs.html?lang=ja)にアップグレードする必要があります。<br/> 2019年2月20日以降、Adobe Analytics data collectionはTLS 1.0をサポートしなくなります。 この変更により、Adobeは、TLS 1.1以降をサポートしていない古いデバイスまたはweb ブラウザーを持つエンドユーザーからAnalytics データを収集しなくなります。 この変更が、お客様の顧客のデータやレポートに大きな影響を及ぼすことはないと認識しています。 （お客様のウェブサイトがTLS 1.0をサポートしていない場合、影響を受けることはありません）。 <br/>2019年4月11日以降、Adobe Analytics Reporting APIはTLS 1.0暗号化をサポートしなくなります。 API にアクセスするお客様は、この変更による影響の有無を確認してください。 デフォルト設定でJava 7を使用している<br/>* API クライアントでは、TLS 1.2[&#128279;](https://www.java.com/en/configure_crypto.html)をサポートするために修正が必要です。 （_クライアントエンドポイントのデフォルト TLS プロトコルバージョンの変更：TLS 1.0からTLS 1.2_&#x200B;を参照）。 デフォルト設定はTLS 1.2であるため、Java 8を使用する<br/>* API クライアントは影響を受けません。 他のフレームワークを使用している<br/>*のAPI クライアントは、TLS 1.2 サポートの詳細についてベンダーに問い合わせる必要があります。 |

| データフィード：post_product_list column - size change | 2019年1月9日 | 2019年2月7日、Adobeはpost_product_list列のサイズを64 KBから16 MBに拡大する予定です。 この変更は、処理中にpost_product_listに追加されたマーチャンダイジング eVarの値が、商品と収益の値の切り捨てを引き起こさないようにするためのものです。 post_product_list値を取り込むプロセスがある場合は、それらのプロセスが最大16 MBの長さの値を処理できることを確認してください。または、データ取り込みエラーを回避するために、16 KBで値を切り捨てます。 |

| レポートに影響するバックエンドの変更 | 2018年4月11日（PT） | （バックエンド）ルックアップメカニズムの変更は、いくつかの点でレポートに影響を与えます。 これらの変更は、2018年2月末頃に有効になりました。ページ名の変更は許可されなくなります。 今後、分類を使用してページ名を変更する必要があります。 2018年5月10日リリースまで、システムは現在設定されている名前の変更されたページを引き続き処理します。 Adobeでは、すべてのユーザーに対し、その日付までに分類に移行するように求めています。 5月のリリース後、既存の名前の変更は適用されなくなり、通知なしに過去にさかのぼって変更できます。<br> <br>URLの置き換え方法が異なります。 以前は、Adobe Analyticsには、毎月、各ページ名に関連付けられた最初のURLが（主に）保存されていました。 今後は、各ページ名の最新のURLを保存します。 （更新日：2018年4月11日（PT）） Reports &amp; Analyticsのロールアップと現在のデータのカテゴリレポートは提供されなくなりました。 Web サービス APIでのカテゴリーロールアップレポートの非推奨（廃止予定）は、2018年5月10日（PT）のAdobe Analytics メンテナンスリリースで有効です。 2007年1月より前（場合によっては2006年）のページ/prop データのサポートは終了しました。 これは、ページ、prop、ページイベント（カスタムリンク、終了リンク、ダウンロードリンクなど）にのみ影響します。 注意：この変更は、Analysis WorkspaceまたはData Warehouseのレポートには影響しません。 これらの日付より前のデータがある場合は、次の点を考慮してください。2007年1月以前/後の境界でデータが正しく結合されない。 検索は、2007年1月頃まではデータに対して機能しません。 |

| データ保持：Adobe Analyticsのデータ保持ポリシーを確認して設定します | 2018 年 2 月 1 日（PT） | **背景：** 2018年5月25日から適用される欧州連合（EU）の一般データ保護規則（GDPR）では、Adobeがデータ処理者として、個人からのアクセス、削除、その他の要求を満たすために適切な対策を講じる必要があると規定されています。 適切で、安全で、タイムリーな削除ポリシーを適用することは、この義務を遵守する上で重要です。 その結果、Adobeは、2018年5月25日にGDPRが施行される前に、お客様と協力してデータ保持ポリシーを実装します。<br> <br>**何を期待するか：** Adobe Analyticsのデータ保持ポリシーを既に導入していない限り、Adobeは、他の取り決めがない限り、Adobe Analyticsのお客様の契約で現在指定されているデータ保持の適用を開始します。 Adobe Analyticsの契約の多くは、Adobeが25か月後にデータを削除する可能性があると述べています。 データ保持ポリシーを組織に対して導入すると、毎月繰り返し適用されます。 データを25か月以上保持する場合は、追加料金で利用できます。 データの保持期間を短くするには、カスタマーケアにお問い合わせください。 まもなく、組織の詳細が記載されたメールが届きます。<br> <br> データ保持は、Reports &amp; Analytics、Analysis Workspace、Report Builder、Web Services Reporting API、データウェアハウス、データフィードなど、過去のAdobe Analytics データにアクセスするためのすべての方法に影響します。 **次の手順：** データ保持に関する意思決定を行う組織内の関係者を特定します。 Adobe Analyticsデータを保持する適切な期間を把握することをお勧めします。 Adobe Analyticsのデータ保持に関するご質問は、Adobe カスタマーサクセスマネージャーまでお問い合わせください。 |
